## A.2 The seven boundary questions

Answers that come from the *directive's own description* are marked **(stated, unverified)**. Nothing was invented.

1. *Natural-language input path already exists?* **Unknown from source.** Directive states CYB1 is numeric/structured and Gen-3 uses a 4-field state: **(stated, unverified)** that there is no NL ingress.
2. *LM connected anywhere?* **Unknown from source.** No LM API, tokenizer, vector DB or memory service is assumed or invented. The pipeline is LM-independent by construction.
3. *External app supplies text?* **Unknown.** The engine therefore exposes `interpret(text, opts)` and a CLI; it does not read from any assumed channel.
4. *Reusable modules?* Cannot be decided without the source. Principles from `asi.reason.hpr` (competing hypotheses, prospective evaluation) are *re-implemented* with a language-appropriate representation instead of reusing a 4-field state.
5. *New modules required?* Everything in `asi.nlu.*` (lexing, lexicon, phrase/entity, semantics, memory, retrieval, verification, record, package, eval).
6. *Where does text preprocessing live?* **Decision: outside VM-1, as application-ingress logic**, with its own deterministic integer work meter (`asi.nlu.util.Meter`). Rationale: it is not part of any evaluated guest's reasoning, and nothing here changes VM instruction semantics, cyber scoring or frozen benchmark behaviour. No unmetered reasoning is inserted into benchmark execution because the pipeline is never invoked from the benchmark path.
7. *Accounting / memory / replay / isolation guarantees?* Cannot be confirmed against VM-1. The NLU layer provides its own: deterministic output (no clock, no randomness at runtime), integer work meter with hard budget → explicit `limited` status, namespace-isolated memory, replayable traces (`interpret-replay`).

## A.4 Critical invariants I will not touch (cannot verify, so the integration is additive only)

- Injection is **additive**: `tools/inject_bundle.lua` inserts one `do … end` block of `package.preload["asi.nlu.*"]`
  registrations; all original bytes after the block are byte-identical (hash verified by the tool).
- If the bundle self-verifies a whole-file or per-module hash, that hash must be regenerated by the bundle's own
  generator — **I cannot do this without seeing it**. The injector prints the before/after SHA-256 so this is auditable.
- Regression of VM / cyber / reasoning / sketch behaviour is **Unproven** until you run your own test command on the
  injected file; `tools/inject_bundle.lua --selfcheck` only proves the injected file still parses (`load`) and that the
  original remainder is unchanged.
